# Ретроспектива 2026-10-19

## Сигналы

- Сессия: синхронный PreToolUse переносил весь период ожидания вопроса в виджет. Наличие успешного ответа из Oasis само по себе не доказывало сохранение штатного интерфейса Claude.
- Сессия: публичные типы mods отличаются от установленной версии. Типы 2.1.296 получены в изолированной CLI-сессии. Проверены настоящий вопрос и отмена pending next при внешнем результате.
- Ревью: запись новых файлов до сохранения владения и преждевременная замена hook entries делали прерванное обновление невосстановимым. Pending manifest теперь сохраняет прежние entries и контрольные суммы обеих версий.
- Сессия: сохраняемая история оставляла выбранным старый запрос. Для ручной проверки использовалась ссылка на точный ID ожидающего запроса.
- Сессия: автоматическая проверка отклонила отключение по непроверенному номеру кнопки, затем отдельное отключение без восстановления в той же команде. Снимком подтверждены подпись и границы, проверка выполнена единой операцией с восстановлением подключения.
- Сессия: файлы типов, созданные Claude рядом с mod, должны пережить отключение. Для повторного подключения сохранена отдельная запись владения.

## Выводы

Основная ошибка была в контракте интеграции. Для двух интерфейсов нужен общий арбитраж результата и отмена проигравшего ожидания, одного фонового hook недостаточно. Нативная проверка должна включать оба направления ответа, а обновление подключения – возможность восстановления после частичной записи.

## Изменения правил

Правила проекта и скилы не менялись. Обнаруженные ошибки исправлены в реализации, ограничения проверки записаны в приёмке. Новых обязательных правил не добавлено.


## Codex: протокол и локальная сборка

### Сигналы

- Диагностический клиент сначала не отвечал на WebSocket ping и терял соединение. Транспорт получил ping/pong, проверку рукопожатия, границы сообщений и поколение соединения.
- Инструкция первой диагностической сессии требовала один вопрос, поэтому запрос двух вопросов проверен в отдельной сессии без этого ограничения.
- Изолированная копия не содержала игнорируемого MediaRemoteAdapter. Перед нативной приёмкой установлена полная сборка с локальной зависимостью. Финальная установка выполнена из основного проекта.
- Ревью нашло возврат из заголовка входящих Codex в Claude. Переход теперь сохраняет провайдера, исправление проверено повторно и нативным UI.
- При попытке двух одновременных UI-действий терминал изменил дерево доступности до нажатия индексной кнопки. Этот прогон не доказывает конкуренцию двух сетевых пакетов. Для действий после изменения состояния нужно заново проверять назначение элемента.
- Диалог доверия общему /private/tmp отменён Esc. Проверка Claude выполнена в уже доверенном проекте Oasis.

### Решения

- Для интеграции использовать официальный app-server установленной версии. Проверять маршрутизацию и завершение настоящими вопросами до реализации UI.
- В доказательствах разделять наблюдение в реальном CLI и вывод по исходникам. Точные ограничения приёмки сохранены рядом с планом.
- Новые правила и скилы не добавлялись. Пользовательские инструкции не менялись.

## Google Meet: открытие комнаты в приложении

- Причина: общий обработчик Join передавал HTTPS-ссылку системному браузеру. Установленный Meet оказался приложением Chrome.
- Открытие ссылки через сам бандл Meet запускало главную страницу и теряло адрес комнаты. Запуск Chrome с ID установленного приложения и параметром `app-launch-url-for-shortcuts-menu-item` сохраняет адрес встречи. Новый процесс передаёт команду уже работающему Chrome.
- Исправлен общий обработчик Join. Если Meet не установлен или запуск завершился ошибкой, используется системное открытие ссылки.
- Ручная проверка: нажата Join в установленном Oasis на демонстрационной встрече. Chrome сообщил точный адрес `https://meet.google.com/abc-defg-hij`, системный список окон подтвердил владельца Google Meet. Подключение к созвону не выполнялось. После проверки возвращён настоящий календарь, демонстрационные комнаты закрыты.
- Проверки: release-сборка завершилась за 11,87 с, `lint: чисто`, подпись установленного приложения прошла `codesign --verify --deep --strict`. Автотесты, фикстуры и тестовые скрипты не создавались и не запускались.
