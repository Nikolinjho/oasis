## Измерения: нативные пружины

Ширина острова мерилась по каждому кадру (`../tools/track.py`, сырые данные в `track-2026-09-26.json`), затем подгонялась модель затухающей пружины с массой 1 (`../tools/fit.py`).

| Переход | Размер, pt | stiffness / damping | ζ | response | Ошибка | SwiftUI-эквивалент |
|---|---|---|---|---|---|---|
| Раскрытие (клик) | 186×32 → 365×175, пик 382×187.5 | **175 / 16** | 0.60 | 0.475 с | 1.7 pt | `.spring(duration: 0.475, bounce: 0.4)` |
| Схлопывание | 365×175 → 186×32 | **250 / 32** | 1.0 | 0.40 с | 0.3 pt | **`.smooth(duration: 0.4)`** |
| HUD: появление | 186 → 374 по ширине, высота 32 | **205 / 28.5** | 1.0 | 0.44 с | 0.4 pt | `.smooth(duration: 0.44)` |
| HUD: скрытие | 374 → 186 | **190 / 28** | 1.0 | 0.46 с | 2.1 pt | `.smooth(duration: 0.45)` |

`.smooth(duration: 0.4)` в SwiftUI — это пружина с k = (2π/0.4)² ≈ 247 и c ≈ 31.4, то есть ровно то, что намерено. Почти наверняка Alcove использует именно её.

### Выводы

- **Раскрытие пружинит, схлопывание нет.** Раскрытие перелетает на +17 pt по ширине (~9.5% хода) и +12.5 pt по высоте, затем оседает примерно за 0.5 с. Схлопывание и HUD идут с критическим затуханием, без отскока.
- **Нативные числа не совпадают с веб-демо.** На сайте расширение почти без перелёта (150/20), а сужение с отскоком. В приложении наоборот. Для прототипа брать нативные значения из этой таблицы.
- **Остров в покое совпадает с вырезом:** 186×32 pt на этом MacBook Pro 16". В настройках notch width = −2 px, это подгонка под железо.
- **Развёрнутый вид:** 365×175 pt. Промежуточное hover-состояние около 203×90, у него свой перелёт до ~206.
- **HUD живёт в строке menu bar:** высота остаётся 32, остров растёт только в ширину до 374. Слева иконка и подпись («Sound», «Display»), справа полоска прогресса.
- Раскрытие и схлопывание масштабируют от центра: левый край уходит на столько же, на сколько растёт ширина, пополам в каждую сторону.

## Хореография смены активностей

Это главная находка записи. Остров **не переходит напрямую** из одного состояния в другое. Сначала он сжимается почти до выреза, потом раскрывается в новое:

```
компакт 261 ──сжатие 0.3 с──► ~190–196 ──раскрытие 0.45 с──► HUD 369
HUD 369     ──сжатие 0.3 с──► ~196–199 ──раскрытие 0.43 с──► компакт 261
```

Раскрытие стартует сразу, как только сжатие дошло до минимума, без паузы. Та же схема у Charging.

| Переход | stiffness / damping | ζ | response | Ошибка |
|---|---|---|---|---|
| Компакт музыки: появление 186 → 261 | 235 / 31 | 1.0 | 0.41 с | 1.4 pt |
| Компакт музыки: уход 261 → 186 | 185 / 27.5 | 1.0 | 0.46 с | 1.2 pt |
| Сжатие перед сменой (261 → ~195) | 345 / 30.5 | 0.82 | 0.34 с | 1.9 pt |
| Сжатие перед сменой (369 → ~199) | 360 / 38 | 1.0 | 0.33 с | 4.9 pt |
| Раскрытие в HUD (195 → 369) | 190 / 24.5 | 0.89 | 0.46 с | 2.3 pt |
| Раскрытие в компакт (199 → 261) | 210 / 27.5 | 0.95 | 0.43 с | 1.3 pt |
| Раскрытие в Charging (195 → 357) | 125 / 20.5 | 0.92 | 0.56 с | 2.2 pt |
| Charging → сжатие | 335 / 37 | 1.0 | 0.34 с | 3.9 pt |

В SwiftUI сжатие берёт замеренные пары по источнику: из компакта `345/30.5` (ζ 0.82, не `.smooth` — demo-сверка 28.09 показала, что `.smooth(duration: 0.33)` ≈ 362/38 недожимает на 2.6 pt к раскрытию), из HUD `360/38` ≈ `.smooth(duration: 0.33)`. Раскрытие — `.spring(duration: 0.45, bounce: 0.1)`. Раскрытие в компактные состояния почти без перелёта: 1–4 pt.

## Смена трека: 3D-переворот обложки

Покадрово в `rec2/track-change-flip.png` (шаг ~33 мс). Сценарий на ~0.65 с:

1. **0 мс:** название уже сменилось. Строка артиста проявляется из блюра.
2. **~130–230 мс:** старая обложка поворачивается вокруг вертикальной оси (`rotation3DEffect` по Y) и сжимается до ребра.
3. **На ребре** подменяется на новую, сильно размытую (~blur 20). Новая доворачивается до фронтального положения, чуть крупнее финала.
4. **~250–650 мс:** блюр плавно уходит до нуля, масштаб оседает к 1.0.

Настройка `disableArtworkFlip` отключает шаг 2–3. Скрипт поиска смен обложки — `../tools/artwork_events.py` (область обложки захардкожена под эту запись).

## Хореография раскрытия с музыкой

Hover из покоя сначала даёт промежуточное состояние **~190×73**. Если навести дольше или кликнуть, ширина скачком становится 370, а высота дорастает до 175 примерно за 0.4 с. В записи №1 при клике из покоя ширина анимировалась плавно, так что вариантов входа два: из покоя и из hover-состояния.
